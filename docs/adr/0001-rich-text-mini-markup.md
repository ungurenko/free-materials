# ADR-0001: richText — безопасная мини-разметка в отдельном модуле

## Статус
Принято

## Дата
2026-08-01

## Контекст
Материалы пишутся в TS-файлах и содержат текстовые блоки с лёгкой разметкой
(`**жирный**`, `*курсив*`, `[текст](ссылка)`). Форматирование жило внутри компонента
`ContentRenderer` и вставляло HTML через `dangerouslySetInnerHTML` без экранирования:
любой HTML из контента исполнялся бы как есть, а ссылки с протоколом `javascript:`
стали бы кликабельными.

## Рассмотренные варианты
- Markdown-библиотека (remark/markdown-it) — полноценный парсер, но для двух-трёх правил
  это лишняя зависимость и вес.
- Оставить как есть в компоненте — не тестируемо, небезопасно.
- Отдельный чистый модуль с экранированием — выбрано.

## Решение
Используем `src/lib/content/rich-text.ts`: чистая функция `formatRichText` с
экранированием HTML до разметки и проверкой протокола ссылок (только `http:`/`https:`).
Компоненты её только вызывают. Валидация контента остаётся на сборке (Zod + loader).

## Последствия
### Плюсы
- Контент не может вставить произвольный HTML или опасную ссылку.
- Логика форматирования тестируется без React (`rich-text.test.ts`).
- Рендер блоков в `ContentRenderer` стал тоньше.

### Минусы
- Ограничение: HTML внутри richText не поддерживается (показывается как текст) —
  авторы материалов должны использовать мини-разметку.

### Нейтральное / на будущее
- Если появятся сложные тексты (таблицы, списки) — рассмотреть замену на библиотеку
  markdown-парсера, оставив тот же интерфейс `formatRichText`.

## Как проверить
- Тест: `src/lib/content/rich-text.test.ts` — экранирование и блокировка опасных ссылок.
- При добавлении блока: если его рендер перестаёт проходить через `formatRichText`,
  это нужно сознательно обосновать.

# Railway + Cloudflare: DNS and incident runbook

Актуально на 21 сентября 2026 года.

## Для каких сайтов

- `free.ungurenko.ru`
- `kzacademy.ungurenko.ru`
- `lmsvibes.ungurenko.ru`

## Главное правило

Для сайтов на Railway запись в Cloudflare по умолчанию должна быть **DNS only** (серое облако).
Cloudflare Proxy включается только после отдельной проверки HTML, CSS и JavaScript с обычной сети
и с телефона. Успешный ответ главной страницы `200` сам по себе не доказывает, что сайт работает.

Cloudflare остаётся авторитетным DNS и может продолжать собирать Web Analytics через отдельный
браузерный beacon. Для этого проксирование DNS не требуется.

## Инцидент free.ungurenko.ru от 21.09.2026

Симптомы:

- Safari долго не завершал загрузку;
- на телефоне открывался неоформленный HTML с огромными SVG;
- главная страница при этом могла отвечать кодом `200`.

Причина: на проблемном маршруте через Cloudflare CSS загружался не полностью, а один из
JavaScript-файлов ожидался около 78 секунд. Код приложения и контейнер Railway были исправны.

Рабочее состояние после ремонта:

- запись `free.ungurenko.ru` — `CNAME`, **DNS only**;
- текущая цель — `vibes-app-production.up.railway.app`;
- рабочий Railway Hikari edge на момент проверки — `69.46.46.41`;
- Railway выбирает сервис по TLS SNI и заголовку `Host: free.ungurenko.ru`, поэтому отдаётся
  приложение Free Materials, а не Vibes LMS;
- HTML и основной CSS отвечают `200` примерно за 0,4 секунды;
- мобильная ширина 390 px проверена визуально, стили применяются полностью.

Текущая CNAME-цель — осознанный обход недоступных с части сетей Railway-адресов, назначенных
непосредственно сервису Free Materials. Если Railway исправит или переназначит официальный edge,
вернуть рекомендованную Railway CNAME-цель можно только после повторной проверки всех ресурсов.
Если домен `vibes-app-production.up.railway.app` будет удалён или переименован, маршрут `free`
нужно обновить.

## Быстрая диагностика

1. Проверить публичный DNS через DNS-over-HTTPS. Обычный DNS-порт 53 в некоторых сетях может
   возвращать перехваченный или устаревший ответ.

   ```bash
   curl -sS 'https://dns.google/resolve?name=free.ungurenko.ru&type=A' \
     -H 'accept: application/dns-json'
   ```

2. Проверить HTML с жёстким ограничением времени.

   ```bash
   curl --max-time 15 -sS --compressed -o /dev/null \
     -w 'status=%{http_code} server=%header{server} ip=%{remote_ip} time=%{time_total}\n' \
     https://free.ungurenko.ru/
   ```

3. Из полученного HTML взять URL основного CSS и JavaScript. Каждый ресурс должен полностью
   загрузиться за 15 секунд, вернуть `200` и правильный `Content-Type`. Маленький обрезанный CSS,
   зависший JS или HTML вместо ресурса считаются аварией.

4. Если HTML работает, а страница выглядит как голый документ, проверить Network в браузере.
   В первую очередь искать зависшие или обрезанные CSS/JS, а не ошибку в React-компонентах.

5. После изменения DNS проверить обычный Safari и мобильную ширину. Визуальная проверка входит
   в критерии восстановления.

## Чего не делать

- Не включать оранжевое облако только потому, что главная страница отвечает `200`.
- Не считать очистку Cloudflare Cache окончательным ремонтом, если CSS/JS продолжают зависать.
- Не менять приложение и не запускать новый Railway-деплой без доказательств ошибки в коде.
- Не полагаться только на локальный DNS-кэш или один резолвер.

## Критерии восстановления

- Публичный DNS возвращает ожидаемый Railway edge.
- HTML, CSS и JavaScript отвечают `200`.
- Каждый ресурс полностью загружается быстрее 15 секунд.
- `Content-Type` соответствует типу ресурса.
- Обычный браузер показывает оформленную страницу.
- Mobile viewport не показывает голый HTML или переполнение.

## Постоянный мониторинг

Почасовой монитор должен проверять все три домена, загружать HTML и найденные в нём CSS/JS с
тайм-аутом, а не ограничиваться HTTP-кодом главной страницы. Пока всё исправно, монитор молчит.
Уведомление отправляется при новой поломке, изменении проблемного состояния или восстановлении.

Ручной запуск той же проверки:

```bash
node scripts/check-production-sites.mjs
```

## 1. Краткое описание

Публичный русскоязычный сайт-каталог бесплатных материалов Александра по нейросетям, маркетингу, продажам, контенту и вайб-кодингу.

Сайт заменяет прежнюю базу в Notion. На главной странице посетитель видит автора, ссылки на социальные площадки, рекламный баннер и общую сетку карточек. Каждая карточка открывает отдельную страницу материала с текстом, изображениями, YouTube-видео, инструкциями, ссылками и промптами.

Админ-панель, авторизация, CMS и база данных отсутствуют. Контент хранится в репозитории и изменяется coding-агентом.

## 2. Цели

- `GOAL-001`: дать посетителю бесплатный материал без регистрации.
- `GOAL-002`: обеспечить копирование промпта одним действием.
- `GOAL-003`: связать материалы с личным брендом автора.
- `GOAL-004`: переводить посетителей в Telegram, Instagram, YouTube и на страницу продукта.
- `GOAL-005`: получать поисковый трафик на отдельные страницы материалов.
- `GOAL-006`: добавлять материалы через агента без изменения базовых компонентов.

## 3. Границы проекта

### Входит в MVP

- главная страница;
- первый экран с фотографией и позиционированием;
- ссылки на Telegram, Instagram и YouTube;
- заменяемый рекламный баннер;
- одна общая сетка без категорий, фильтров и поиска;
- 1–2 реальных материала на запуске;

- отдельная страница каждого материала;
- универсальные контентные блоки;
- YouTube-видео;
- копирование полного промпта;
- адаптивность;
- SEO;
- аналитика посещений и действий без cookies;
- страница 404;
- деплой на Vercel;
- инструкция по добавлению материалов.

### Не входит

- личный кабинет;
- админ-панель;

- комментарии, рейтинги и реакции;
- мультиязычность;
- собственный видеохостинг;

### Возможные будущие улучшения

Категории, поиск, второй язык, RSS, каталог продуктов, собственный домен, перенос на Railway и CMS при реальной необходимости.

## 4. Целевая аудитория

Эксперты, блогеры, маркетологи, продюсеры и начинающие пользователи ИИ. Основной контекст — переход из социальных сетей или поиска с телефона и быстрое использование материала в ChatGPT, Claude, Codex или другом ИИ-инструменте.

## 5. Роли

### Посетитель

Может просматривать все опубликованные материалы, копировать промпты, смотреть YouTube, переходить по внешним ссылкам. Не может изменять контент.

### Владелец

Меняет контент, ссылки и баннер через coding-агента и Git. Просматривает аналитику во внешнем сервисе.

## 6. Основные сценарии

### US-001 — Просмотр каталога

GIVEN посетитель открыл главную  
WHEN страница загрузилась  
THEN он видит автора, рекламный баннер и карточки опубликованных материалов.

### US-002 — Открытие материала

GIVEN карточка видна в каталоге  
WHEN посетитель активирует её мышью, касанием или клавиатурой  
THEN открывается отдельная страница материала.

### US-003 — Копирование промпта

GIVEN prompt-блок отображён  
WHEN посетитель нажимает «Скопировать»  
THEN весь текст соответствующего промпта помещается в буфер обмена и появляется состояние «Скопировано».

ЕСЛИ Clipboard API недоступен  
THEN интерфейс показывает понятную ошибку и сохраняет возможность вручную выделить текст.

### US-004 — Просмотр видео

GIVEN материал содержит валидный YouTube ID  
WHEN посетитель активирует превью  
THEN загружается адаптивный privacy-enhanced YouTube player.

### US-005 — Добавление материала

GIVEN агент создал валидный файл материала  
WHEN выполняется сборка  
THEN карточка, маршрут, metadata и sitemap создаются без нового page-компонента.

## 7. Функциональные требования

### Каталог

- `FR-001`: система ДОЛЖНА выводить опубликованные материалы в одной сетке.
- `FR-002`: категории, поиск, фильтры и пагинация НЕ ДОЛЖНЫ отображаться.
- `FR-003`: карточка ДОЛЖНА содержать обложку, название, описание и метку формата.
- `FR-004`: вся карточка ДОЛЖНА быть интерактивной и доступной с клавиатуры.
- `FR-005`: порядок карточек ДОЛЖЕН задаваться полем `order`.

### Первый экран и ссылки

- `FR-006`: hero ДОЛЖЕН содержать фотографию, имя, позиционирование и описание базы.
- `FR-007`: ДОЛЖНЫ присутствовать отдельные ссылки Telegram, Instagram и YouTube.
- `FR-008`: внешние ссылки ДОЛЖНЫ открываться с `noopener noreferrer`.

### Рекламный баннер

- `FR-009`: баннер ДОЛЖЕН быть отдельным компонентом.
- `FR-010`: конфигурация ДОЛЖНА поддерживать `enabled`, тексты, ссылку, кнопку и изображение.
- `FR-011`: при `enabled=false` блок НЕ ДОЛЖЕН оставлять пустое место.

### Материалы

- `FR-012`: каждый материал ДОЛЖЕН иметь уникальный slug.
- `FR-013`: страница ДОЛЖНА собираться из упорядоченного массива блоков.
- `FR-014`: обязательные типы блоков: rich text, heading, image, YouTube, prompt, link, note и divider.
- `FR-015`: один материал МОЖЕТ содержать несколько prompt-блоков.
- `FR-016`: неизвестный или невалидный блок ДОЛЖЕН останавливать проверку либо сборку с понятной ошибкой.

### Копирование

- `FR-017`: кнопка ДОЛЖНА копировать полный текст только своего prompt-блока.
- `FR-018`: состояние «Скопировано» ДОЛЖНО показываться 1,5–3 секунды.
- `FR-019`: результат копирования ДОЛЖЕН сообщаться скринридеру через live region.

### YouTube

- `FR-020`: блок ДОЛЖЕН принимать валидный video ID или нормализуемый URL.
- `FR-021`: embed ДОЛЖЕН использовать `youtube-nocookie.com`.
- `FR-022`: iframe ДОЛЖЕН создаваться после действия пользователя; `loading="lazy"` используется как дополнительная защита.
- `FR-023`: соотношение сторон ДОЛЖНО быть 16:9.
- `FR-024`: ДОЛЖНА быть fallback-ссылка «Смотреть на YouTube».

### Конфигурация и 404

- `FR-025`: данные автора, ссылки, SEO и баннер ДОЛЖНЫ храниться отдельно от UI.
- `FR-026`: материалы ДОЛЖНЫ храниться отдельно от компонентов.
- `FR-027`: проект ДОЛЖЕН содержать пример материала и инструкцию по добавлению.
- `FR-028`: неизвестный slug ДОЛЖЕН показывать кастомную 404.
- `FR-029`: 404 ДОЛЖНА содержать возврат к каталогу.

- `/materials/[slug]` — материал;
- 404 — неизвестный маршрут;

### Основные модули

## 9. Экраны

### Главная

Порядок: шапка → hero → рекламный баннер → заголовок раздела → сетка → Telegram CTA → футер.

На широком экране карточки выводятся в две колонки, на телефоне — в одну. При отсутствии материалов показывается спокойное пустое состояние, однако production-релиз не считается готовым без минимум одного материала.

### Материал

Возврат к каталогу → метка → H1 → лид → обложка → динамические блоки → Telegram CTA → возврат к каталогу.

Основной текст должен присутствовать в исходном HTML без обязательного клиентского JavaScript.

### 404

Короткое сообщение и кнопка возврата на главную.

## 10. UX/UI

Стиль: Notion × Apple.

- молочно-белый фон;
- тёмно-серый текст;
- приглушённый салатово-зелёный акцент;
- крупная спокойная типографика;
- много воздуха;
- мягкие скругления;
- тонкие границы и деликатные тени;
- короткие анимации без тяжёлых эффектов;
- поддержка `prefers-reduced-motion`;
- размер основного текста от 16 px;
- интерактивные зоны на телефоне рекомендуется делать от 44×44 CSS px;
- focus-visible обязателен;
- цвет не является единственным способом передачи состояния;
- отсутствие горизонтального скролла на ширинах 320, 375, 768, 1024 и 1440 px.

## 11. Технический стек

### Рекомендация

- Next.js App Router;
- React;
- TypeScript strict;
- статическая генерация страниц;
- CSS Modules либо Tailwind CSS, если он уже есть в прототипе;
- Zod или эквивалент для схемы контента;

Версии не закрепляются в этом документе. При реализации используются актуальные стабильные совместимые версии и lockfile.

Если импортированный прототип создан на React/Vite, агент сначала оценивает качество и стоимость миграции. Миграция на Next.js обязательна, если текущий SPA не выдаёт отдельный индексируемый HTML, корректные metadata, sitemap, robots и OG для каждого материала.

## 12. Архитектура

Статическое монолитное приложение без server-side business logic.

Поток данных:

1. config и content читаются во время сборки;
2. схема валидирует данные;
3. опубликованные материалы формируют каталог;
4. статические параметры создают маршруты;
5. те же данные создают metadata, sitemap и OG;
6. клиентский JS используется только для копирования, аналитики и активации видео.

Рекомендуемое разделение:

```text
src/
  app/
  components/
  content/materials/
  config/
  lib/content/
  lib/seo/
  lib/youtube/
  lib/analytics/
  types/
public/images/
docs/adding-materials.md
```

## 13. Модель данных

### SiteConfig

`siteName`, `siteDescription`, `siteUrl`, данные автора, фотография, social links, promo config, analytics config.

### Material

`slug`, `title`, `summary`, `formatLabel`, `coverImage`, `coverAlt`, `publishedAt`, `updatedAt`, `order`, `published`, `seo`, `blocks`.

### ContentBlock

Discriminated union по `type`:

`richText`, `heading`, `image`, `youtube`, `prompt`, `link`, `note`, `divider`.

### PromptBlock

`id`, `title?`, `description?`, `prompt`, `collapsed?`.

### YouTubeBlock

`videoId`, `title`, `description?`, `startAt?`.

## 14. Интеграции

### YouTube

Формировать URL через `https://www.youtube-nocookie.com/embed/{videoId}`. Не принимать произвольный HTML. Использовать thumbnail-first и создавать iframe после действия пользователя. Всегда сохранять прямую ссылку на YouTube.

### Umami

Использовать pageviews и custom events без cookies.

События:

- `material_open`;
- `prompt_copy`;
- `social_click`;
- `promo_click`;
- `youtube_play`;
- `telegram_cta_click`.

Допустимые свойства: `material_slug`, `platform`, `placement`, `promo_id`.

Не передавать имя посетителя, email, полный текст промпта или другие персональные данные. При отсутствии конфигурации аналитика становится no-op и не ломает сайт.

## 15. Безопасность и приватность

- не собирать персональные данные;
- не передавать их в аналитику;
- не рендерить raw HTML без санитизации;
- валидировать YouTube ID;
- не хранить секреты в клиентском bundle;
- настроить совместимые security headers;
- проверить зависимости;
- использовать безопасные атрибуты внешних ссылок.

Решение об отсутствии отдельной privacy page основано на cookie-free аналитике и отсутствии форм. Оно не является юридической гарантией и должно быть пересмотрено при изменении интеграций, географии или модели сбора данных.

## 16. Производительность

- `NFR-001`: LCP — цель не выше 2,5 с на 75-м перцентиле.
- `NFR-002`: CLS — не выше 0,1.
- `NFR-003`: INP — не выше 200 мс.
- `NFR-004`: изображения имеют размеры или aspect ratio.
- `NFR-005`: hero-фото оптимизировано.
- `NFR-006`: YouTube iframe не загружается заранее.
- `NFR-007`: основной текст доступен без клиентского JS.
- `NFR-008`: неиспользуемые библиотеки удалены.

## 17. SEO и аналитика

### SEO

- уникальные title и description;
- canonical URL;
- Open Graph и Twitter Card;
- индивидуальное или сгенерированное OG-изображение;
- sitemap и robots;
- только опубликованные материалы в индексе;
- один H1;
- корректные alt;
- JSON-LD только подходящего фактическому содержанию типа, например Article, HowTo или VideoObject.

### Аналитика

Отслеживать pageviews, открытие материала, успешное копирование, переходы в соцсети, клик по баннеру и запуск YouTube. Блокировка аналитики не должна влиять на основной сценарий.

## 18. Тестирование

### Unit

Схема Material, уникальность slug, нормализация YouTube URL, canonical URL, сортировка, фильтрация опубликованных материалов и analytics mapping.

### Component

Копирование, состояние «Скопировано», ошибка Clipboard API, скрытие баннера, клавиатурная карточка и lazy YouTube.

### E2E

- главная показывает карточки;
- карточка открывает материал;
- копирование работает;
- неизвестный slug показывает 404;
- social и promo links корректны;
- нет горизонтального скролла;
- sitemap содержит только опубликованные URL;
- metadata соответствует данным;
- сайт работает при заблокированной аналитике.

### Ручная проверка

Safari, Chrome, Firefox, мобильные ширины, клавиатура, VoiceOver, reduced motion, слабое соединение и social preview.

## 19. Этапы реализации

1. **Аудит прототипа:** изучить репозиторий, запустить build/typecheck/lint/tests, определить необходимость миграции.
2. **Архитектура данных:** config, schema, content loader, первый реальный материал.
3. **Главная:** hero, соцсети, баннер, сетка, CTA, responsive.
4. **Материалы:** universal renderer, prompt copy, YouTube.
5. **SEO:** metadata, canonical, OG, sitemap, robots, JSON-LD, 404.
6. **Аналитика:** Umami и события с no-op fallback.
7. **Качество:** тесты, accessibility, performance, документация.
8. **Деплой:** Vercel, environment config и production-проверка.

После каждого этапа обязательны релевантные проверки.

## 21. Риски, допущения и открытые вопросы

### Риски

- бесплатный генератор создаст SPA с плохим SEO;
- прототип будет перегружен зависимостями;
- YouTube ухудшит загрузку;
- некорректная schema-разметка навредит SEO;
- перенос на новый домен создаст дубли;
- юридические требования могут измениться при смене аналитики или географии.

### Снижение рисков

Аудит репозитория, миграция при необходимости, thumbnail-first YouTube, централизованный `siteUrl`, строгая schema, минимум зависимостей и отдельная юридическая проверка при изменении модели данных.

### Допущения

Фотография, ссылки, тексты hero, баннер, домен, первые материалы и финальные обложки будут предоставлены при наполнении.

### Открытые вопросы перед production

- финальное название;
- фотография;
- ссылки;
- текст первого экрана;
- содержимое баннера;
- production-домен;
- 1–2 материала;
- OG-изображения.

Эти данные не блокируют архитектуру, но блокируют финальное production-наполнение.
